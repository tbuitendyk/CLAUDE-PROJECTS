Required by research-loop step 7 before any new job may be fired.

week. Answer all of them in writing, including the uncomfortable ones. "No

## 1. What was this run supposed to answer?

State the question as it was written BEFORE the run started. Quote the
launcher's reading rule. If the question was never written down in advance,
that is itself a finding — record it and fix it for next time.

## 2. Does the output answer THAT question, or a neighbouring easier one?

The classic substitution here: asking "is this predictive?" and answering "is
this profitable on the window we used to choose the settings?" Name the
question actually answered.

## 5. Are the two compared arms the same population?

Real versus null, before versus after, group A versus group B. Check the
composition, not just the headline. The silent-unit rate was 2.4% real against
15% scrambled — two different populations compared as one.

## 6. Is any part of the reported number achievable with NO skill?

Always-guess-the-commonest-answer, always-say-flat, always-long in a rising
market. Quantify it. If it has not been measured against noise, say so.

## 7. Would this number look the same on pure noise?

If no null has been run against this exact metric, the honest answer is "not
known", not "probably not".

## 8. What did I assume and not verify?

List everything. For each: verified now / recorded as an open gap. Nothing
gets left as "cheap to check" — a flagged-and-unchecked assumption is how the
silent-unit defect survived.

## 9. Is the previously planned next step STILL correct?

The default answer is NOT "yes". Given 1-8, either:
- the planned step proceeds unchanged, and why; or
- **an intervening step is inserted first** — name it, and say what it fixes.

There is no budget limit on intervening steps. A wrong instrument makes every
downstream run worthless, so fixing it is never the expensive option.
