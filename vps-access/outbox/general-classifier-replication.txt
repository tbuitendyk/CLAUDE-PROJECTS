THE SINGLE CONFIG IS UNCHANGED

Worth saying first because it is the thing that must not break. With no permute
tick the expansion returns exactly the one config, and every row the run records
is the row it always recorded. That is pinned by a test, not by intention.

WHAT PERMUTING DOES

A permute tick sits beside each replication box — entry, gate, d, t, trail, arm,
agree. Tick any and every combination becomes its own declared config, each one
scored on every asset.

Every member is put through the SAME validator a single declaration passes
through. That is deliberate: one rule decides what a legal declared config is, so
a permuted set can never contain something the single path would have refused — a
gate on a market cell, an arm with no trailing stop. Ticking arm while the stop
is static declares one config, not three copies of the same one.

The form now tells you the count BEFORE you press Start sweep, because a number
you only discover from a refusal message is a number you found too late. Over 500
configs it refuses and says how many were asked for.

Cost: no extra sweeping. Every cell was already computed and pooled for the
region work, so each declared config is a lookup. Each one does get its own
held-back score — the replication tally reads the held-back window, and a member
without one would shrink the denominator silently.

One thing to keep in view: permuting means you searched, so the result is not
declared in the strict sense any more. The honest end of that search is the
sealed slice — window layout 61/13/13/13, graded once in History. The form says
so where you tick.

THE REPLICATION TABLE

The tick's tooltip has been promising "a separate replication table reporting the
declared cell per asset" while the Constructing tab showed nothing at all. The
run has been recording those rows the whole time; no screen displayed them.

Boards now shows them, grouped per declared config when there is more than one.
Each group carries the tally that is the entire point of replication — one look
per asset, so the count across assets owes no shopping tax and needs no
correction.

Table: what a replication group reports.
Key — held-back positive: how many assets made money on the once-only look;
1-in-N: how unlikely that split is on coin flips; beat always-long: same count
against forcing the position long every period.

  reading                      what it answers
  held-back positive k/n       did the declared cell hold up across assets
  1-in-N by coin flip          could that split happen by chance alone
  beat always-long k/n         did the calls earn their keep vs just being long

Null copies also score the declared cell — that is their job — and they are
excluded from every count here.

FOUND AUTOMATICALLY, WORTH NOTING
