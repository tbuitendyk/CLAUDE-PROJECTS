THE ONE THAT WAS NOT EVEN REACHABLE

The trading fee was hard-coded inside the engine. No launcher could change it.
That is the same class of fault as the API silently dropping "trailing" and
"holdout" earlier this week, and it matters more, because cycle 9's entire
result stands on the fee: 86 cents of every dollar earned goes to fees, and
break-even sits only 16% above the cost we ASSUME.

So the one number the answer depends on could not be moved.

Worse, my own guard test could not see it. That test checks every setting the
engine reads from the caller is actually forwarded — but a setting sourced from
a constant is never read from the caller, so nothing looked missing. It
reported all clear.

The guard now checks the other direction too: anything the sweep consumes must
be traceable back to something a caller can set. And I had to fix that check
three times before it worked — the first two versions passed the suite while
detecting nothing, which is its own lesson and is now QC 44: a check is not
trusted until the fault is put back and it fails.

WHY THE FEE NOW JUMPS AHEAD OF TRAILING STOPS

I told you last night trailing was next. It is not, and here is the reasoning:

1. It decides whether anything else matters. If the edge dies at realistic
   execution costs, trailing and multi-asset are moot.
2. It expands nothing. Changing the fee re-scores the same trades; it adds no
   new dimension to search, so it cannot manufacture a lucky winner. In
   selection-risk terms it is the safest test available.
3. It has never been examined, and now we know it could not have been.
