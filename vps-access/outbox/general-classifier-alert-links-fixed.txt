One line in each of the two alerters, both pointing at

AN HONEST LIMIT ON THAT CHECK

The list of pages that exist lives on the classifier branch; the alerters live
on the carrier branch. So the test compares the link against a fixed string,
not against what the server actually serves. That catches the rot that just
happened — a page being deleted from under the link — but a page being RENAMED
would pass both tests and break both links again. Written up as QC 198 with
that gap stated rather than glossed. Closing it properly means the test asking
the running server whether the URL resolves, which I have not built.
