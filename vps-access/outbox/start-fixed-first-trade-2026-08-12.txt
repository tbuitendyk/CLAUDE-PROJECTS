The bug
-------
Pressing START opened the confirm box, but on OK nothing happened. Cause: the
server's arm/disarm (and stop-sweep) endpoints referenced a variable `fs` that
the server never defines — it holds the file module under the name `dataFs`. So
every START press threw a 500 error server-side and wrote no arm request. The
screen's button code does not check the response, so the error was invisible: the
dialog just closed. It stayed hidden through every review because these endpoints
had never actually been called until your first real START press — no test drove
the running server over HTTP, and the deploy health check only does a read.

Fix: point every bare `fs` at the real `dataFs`. Pushed, deployed, service
restarted 01:04:39 UTC, and confirmed against the live server (the endpoint now
returns 200 and writes the request the box reads).
