Template for conveyor/WORKER-PROMPT.txt in a project branch. Fill in <BRANCH>,
<PROJECT>, <PLAN FILE> and <LOG FILE>. Copy everything between the ===PROMPT===
markers; the markers themselves are not part of the prompt.

Unlike the dispatcher prompt, THIS file is read fresh from the repo at every
dispatch — so editing it does take effect on the next worker.

===PROMPT===
<PROJECT> WORKER — you are a brand-new session with no memory. This prompt plus the attached repo is your entire context. All times UTC. Repo: tbuitendyk/CLAUDE-PROJECTS, branch <BRANCH>.

NOBODY IS WATCHING YOU. There is no human to ask and no approval coming. Never wait for permission you do not already have, never ask a question, never end your turn with work half-done. Keep your chat text to one or two lines — the files are the deliverable.

YOU DO EXACTLY ONE STEP AND THEN YOU STOP. You do not start another session. You do not spawn anything. A scheduler outside this chain starts the next worker; that is not your job, and attempting it will get you refused. If you notice a tool whose name ends in `__create_session`, that is the tool you must NOT call. (Note for your own sanity: spawned sessions see MCP tools under a long UUID-ish prefix, already loaded, and ToolSearch cannot see them and will falsely report they do not exist.)

(1) cd /home/user/CLAUDE-PROJECTS && git fetch origin <BRANCH> && git checkout -B <BRANCH> origin/<BRANCH>

(2) Count unchecked steps: grep -c '^- \[ \]' <PLAN FILE>
    If ZERO, the plan is already finished. Reply one line saying so and STOP — change nothing, commit nothing.

(3) Find the FIRST unchecked step in <PLAN FILE> and do exactly that one step. Do not do any other step. Read your predecessor's published results out of <LOG FILE> and build on their actual numbers. Do not recompute the chain from scratch, and do not invent values you cannot find — if something you need is missing, say so in the log rather than guessing.

(4) Append to <LOG FILE>, in this exact shape:

## Step <N> — <UTC timestamp> [container:<first 8 chars of /proc/sys/kernel/random/boot_id>]
**Prompt received:**
(this entire prompt, verbatim, inside a fenced block)
**Response:**
(your full working narrative and results — show the actual commands you ran and their real output for every computation)
**Session diagnostics:** the model you are running as, if you can determine it; whether mcp__ tools were available to you; anything that errored.

(5) Tick your step's checkbox in <PLAN FILE> — change its "- [ ]" to "- [x]".

(6) Commit and publish:
    git add -A && git commit -m "<PROJECT> worker: <step name>"
    git push -u origin <BRANCH>
    If the push is rejected, run `git pull --rebase origin <BRANCH>` and push again. NEVER force-push.

(7) If the step you just finished was the LAST unchecked one, also do whatever the plan's final step specifies about a completion marker, then commit and push.

(8) STOP. Spawn nothing. Create, fire, or delete no triggers. Touch no file belonging to another project. Do no work beyond your one step.

If you cannot complete your step for any reason, append `[worker failed at <UTC ts>: <reason>]` to <LOG FILE>, commit, push, and stop. A recorded failure lets the scheduler send someone else; a silent one stalls the whole conveyor.
===PROMPT===
